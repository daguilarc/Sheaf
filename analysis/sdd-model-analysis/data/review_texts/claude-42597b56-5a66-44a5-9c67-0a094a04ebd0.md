**Minor:**

1. **`DspMath.hpp:145`** — the variable `outputT` names the narrowed *input* time (post-clamp, pre-shaping), not the function's output. It's read at lines 147–148 to compute `smoothT`/`shapedT`, none of which is the return value. Suggest renaming to `narrowedT` (or `floatT`) so the one-narrowing-point invariant reads clearly at the call sites, e.g.:
   ```cpp
   const float narrowedT = static_cast<float>(clampedT);
   const float smoothT = 0.5f - 0.5f * DefaultDspMath::Cos2Pi(0.5f * narrowedT);
   const float shapedT = clampedShape * smoothT + (1.0f - clampedShape) * narrowedT;
   ```

2. **`dsp_tests.cpp:305-341`** — `correlated_increments_reject_invalid_config` covers `muSeconds = NaN` but not `muSeconds = +infinity`, even though `ValidateRandomTimingConfig` (`DspRandomLfo.hpp:88-90`) rejects both via the same `!std::isfinite(...)` check. The infinite-sample-rate case already exercises the isfinite-vs-infinity path elsewhere, so risk is low, but for full landmark coverage add:
   ```cpp
   invalid = valid;
   invalid.muSeconds = std::numeric_limits<double>::infinity();
   REQUIRE_TRUE(rejects(48000.0, invalid));
   ```
