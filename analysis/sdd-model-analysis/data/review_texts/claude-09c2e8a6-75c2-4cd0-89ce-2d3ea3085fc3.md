**2. Code quality: Important findings (2), plus one Minor.**

- **Important — duplicate "Type" column header.** `Field::BlockMessageType` and `Field::AddressType` both return `"Type"` from `FieldShortLabel` (`MidiConfigViewModel.cpp:356-359`). For a Generic system-message Block row, `SystemBlockEditableFields` (`MidiConfigViewModel.cpp:779-785`) places both fields adjacently, so the Controllers page renders two side-by-side header cells that both read "Type" — one for Scene/Bank/Gesture-select, one for the new CC/Note selector — with no way to tell them apart. Fix: give `AddressType` a distinct short label (e.g. `"Addr"`).

- **Important — Makefile stale-object gap (pre-existing, deepened by this task).** `MidiConfigViewModel.o`'s prerequisites (`Makefile:75`) and the `viewmodel_tests`/`controllers_page_ui_tests` binary rules (`Makefile:136`, `151`) omit `include/synth/MidiConfigBlocks.hpp`, despite `MidiConfigViewModel.hpp` including it and now consuming its types (`SystemAddressField`, `EncoderBlock::controlType`, `SystemBlock::controlType`). This wasn't introduced by Task 3, but Task 2 exposed it and Task 3 deepens reliance on it — a future `MidiConfigBlocks.hpp`-only edit will leave `MidiConfigViewModel.o` stale under incremental `make`, risking silent ABI/struct-layout mismatches (this is exactly what caused the segfault the implementer worked around locally with `make -B`, per the report's "Baseline Build Note"). This should be fixed (add the missing header prerequisite) before the overall change is archived — it doesn't need to block Task 3's own commit, since Task 3's functional changes are independently correct and were verified via a forced rebuild.

- **Minor — test-coverage gap.** No test exercises invalid (fractional/out-of-range) `AddressType` indices on Block rows (only Individual rows are covered); the block-path validation code mirrors the tested individual-row logic, so this is low-risk but currently unverified.
