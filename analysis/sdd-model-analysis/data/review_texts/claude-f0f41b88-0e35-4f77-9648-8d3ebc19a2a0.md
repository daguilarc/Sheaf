### Non-blocking observations (for the code reviewer, not spec gaps)

1. **`DspAutoScope.hpp:1904-1920` — prominence uses the global second-best score.** Because adjacent offsets `k·span/64` are highly correlated near a sharp periodic peak, the runner-up is often the immediate neighbor, which can hold `peak-runnerUp` below 0.08 and suppress acceptance of exact-periodic history. This is spec-consistent (design.md:168 / sdsp-39:74 say only "prominence at least 0.08", no non-adjacency requirement) and the periodic test doesn't require `AcceptedAlignments>0` (bootstrap seed + unshifted accumulation still form the ridge), so it's not a violation — but worth a code-review confirmation that the intended registration behavior is achieved rather than relying on the unshifted path.

2. **`DspAutoScope.hpp:1919, 1938-1941` — `AlignmentOffsetEvaluations` invariant.** Offset evaluations are counted before `AccumulateDensitySpan`; if a span passes offset-0 sampling and the offset search but then `AccumulateDensitySpan` returns false (all columns unreadable → `break`), evals are counted for a span that doesn't increment `completeSpans`, so the tested identity `(CompleteSpans-1)·17` could break. Not reachable in the current test signals (once the 128-sample window reads, the 256 raster reads succeed), and it's diagnostic-only.

3. **`DspAutoScope.hpp:800` — testing shim divergence.** `DensityReaderForSourceTesting` still calls `CommonDensityAnchorBase()` while production now uses `DensityAnchorBase(level, source)`. Testing-only helper; harmless, but its anchor no longer matches the production path it emulates.

None of these block the spec review. The change realizes sdsp-39 completely.
