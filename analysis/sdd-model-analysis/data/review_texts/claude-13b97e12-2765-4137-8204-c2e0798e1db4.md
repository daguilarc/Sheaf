## Findings

### Minor

**M1 — `Reader::Get` is not `noexcept` and can throw from the 1024-point draw hot path under non-default configs.**
Location: `DspAutoScope.hpp:125-132` (`Get`) → `DspLogStructuredBuffer.hpp:253-276` (`Read`).
`Get` clamps its index to `[oldestIndex_, newestIndex_]`, but if a *non-default* config lets `renderWavelength` collapse toward 0 (e.g. `minLag=1` with a parabolic offset near `-1`, making `fractionalLag ≈ 0`), `CreateReader:392` divides by `renderWavelength` and produces NaN indices; `std::clamp(NaN,…)` returns NaN, and `Read` then throws `out_of_range` on the `!isfinite` guard. `BuildScopePolylines` (`PortableUIBuilders.hpp:99-119`) calls `Get` 1024×/frame with no try/catch, so a throw would escape `DrawVisible` into the paint callback. Not reachable with the pinned defaults (`minLag=8` ⇒ wavelength ≥ 7), and no app adopts AutoScope yet. Concrete fix: make `Get` `noexcept` and return `0.0f` for a non-finite index, or reject `renderWavelength < ~1` in `CreateReader` before mapping.

**M2 — `std::terminate()` on the realtime producer thread at sequence exhaustion.**
Location: `DspAutoScope.hpp:670-673` (`Publish`). Guarding tag overflow with `std::terminate()` is a heavy hammer for a DSP callback. It is genuinely unreachable (`kMaximumSequence ≈ 4.6×10¹⁸` samples ≈ 10⁵+ years at 192 kHz) and is documented, so this is informational only — no action required, but worth a one-line comment noting the deliberate choice.

**M3 — Per-slot `is_lock_free()` loop over the full transfer capacity at construction.**
Location: `DspAutoScope.hpp:225-231`. Lock-freedom is a per-type/alignment property, so the 262,144-iteration `is_lock_free()` check is redundant work (the atomics are also zero-initialized in the same loop, which is needed, so the loop itself is justified). Harmless one-time cost; a `static_assert(std::atomic<...>::is_always_lock_free)` would be cheaper and stronger. Non-blocking.
