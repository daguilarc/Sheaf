### Minor

**M1 — Base `SetConfig` hiding is defensive-only, not airtight (`MidiController.hpp:514`, `MidiController.cpp:918`).**
`GenericMidiOutProcessor` privatizes reconfiguration with `using MidiOutProcessor::SetConfig;`. This blocks calls through a `GenericMidiOutProcessor*` reference, but `MidiOutProcessor::SetConfig(EncoderMidiOutConfig)` is **public and non-virtual** on the base, so a caller holding a `MidiOutProcessor*` (static type) bound to a Generic object could still invoke the base implementation, replacing `config_.mappings` while leaving `outputAddresses_` stale — a cardinality desync (`assert` in debug, out-of-bounds `outputAddresses_[ix]` in release). Verified this is not an actual defect: there are **zero call sites** for the encoder-output `SetConfig` anywhere in `src`/`include`/`app`/`tests` (the one `.SetConfig(` hit at `parameter_modulation_tests.cpp:6246` is a `SystemButtonMidiInProcessor` input), and outputs are stored/handled only as `unique_ptr<MidiOutputProcessor>` (the abstract base, which has no `SetConfig`), with no downcasts to `MidiOutProcessor*`. So the hiding is **sufficient in practice**; the base method is effectively dead code. Optional hardening: delete/protect the unused base `SetConfig`, or make it virtual. Not blocking.

**M2 — Redundant projected `mapping.cc` (`MidiController.cpp:279-284`).**
`ProjectInput` stores `mapping.control.cc` into the projected `EncoderMidiOutConfig::mappings[i].cc`, but Generic never sends from `config_.mappings.cc` — `ProcessPosition` sends from `outputAddresses_[i]`, and route reservation/snapshot use only `slotIx`/`position`. The stored `cc` is inert. Harmless (keeps the base config shape) but slightly misleading. Not blocking.

**M3 — Empty-`turns` Generic profile yields a no-op output processor (`MidiController.cpp:1997`).**
The factory gates only on `encoderInput.has_value()`, so a Generic profile with zero turns still constructs a `GenericMidiOutProcessor` whose `Process()` does nothing. Negligible; matches the spec's "at most one" wording.
