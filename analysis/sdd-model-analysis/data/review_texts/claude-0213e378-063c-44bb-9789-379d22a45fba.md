## Task 5 Spec-Compliance Review

**Verdict: Not fully compliant — two confirmed gaps (findings below), everything else checks out.**

### Findings (most severe first)

1. **`midi-flow.spec.ts:311-328`** — The new real-WASM test computes `outboundA` (slot A's output traffic) but never asserts it stays empty; only `outboundB` is checked. The brief explicitly requires proving "outbound SysEx reaches only that slot's output" — the isolation half of that claim is unverified. A regression that broadcasts outbound SysEx to every output would still pass this test.

2. **`miniapp-smoke.spec.ts:13-28`** — This `beforeAll` still polls a gate file to confirm "fake app ran first," but the rewritten `fake-app.e2e.spec.ts` no longer writes that file anywhere (the old write-gate-file block was deleted along with the old monolithic test). Both current documented invocations (`browser/Makefile:35`, task-5-brief Step 5) always set `SYNTH_BROWSER_FAKE_GATE_CONFIRMED=1`, so this doesn't currently break CI — but the fallback path is now permanently broken: running `miniapp-smoke.spec.ts` directly without that env var will always time out and fail after 20s, even if the fake-app test just passed. Dead/misleading safety net.

3. **`midi-flow.spec.ts:292`** (low confidence, flagged for awareness) — `dispatch-action runtime.controllers.add_controller` with value `"peer:wrldbldr"` has no assertion on its effect; unclear if it's required to provision slot 1 or vestigial. Not a confirmed defect since the test evidently passes, just unclear/uncommented.
