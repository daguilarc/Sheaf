### Issues

#### Minor

**M1 — Tasks marked complete before review approval** (`openspec/changes/decouple-encoder-block-rate/tasks.md`)

The brief's Step 6 says "After review approval, change tasks 1.1 through 1.5 … from `- [ ]` to `- [x]`." The implementer marked them `[x]` in the implementation commit, not a post-approval commit. This short-circuits the review gate that Step 6 was designed to enforce. The tasks should remain `[ ]` until this review approves.

**M2 — Depth parameters are double-computed at interval boundaries**

Modulation-depth parameters are created via `group_.CreateLocalParameter`, which increments `parameterCount_`. So `ParameterGroup::ProcessSample` calls `depth->ProcessSample(sampleIndex)` directly from the loop. At interval boundaries, `carrier.Compute()` already recursed into `depth->ComputeAtDepth()` (setting its `targetCenter_`), then the loop reaches the depth's own slot and calls `depth->Compute()` a second time — same scene, same result, no correctness harm, but wasted work.

This is not a bug. It is worth documenting so Task 2 (engine integration) does not multiply the cost at scale by assuming each `ProcessSample` call is O(1) work per slot.

**M3 — Group test does not isolate the recursive-Compute path from the direct-loop path**

`parameter_group_process_sample_covers_top_level_and_modulation_depth_targets` verifies `depth->TargetCenter() == 0.5f` after `group.ProcessSample(0)`. This assertion is satisfied by both:
- (a) the carrier's `Compute` recursively updating the depth's `targetCenter_`, and  
- (b) the depth's own `ProcessSample` in the loop.

Path (b) alone would produce the same observable result. If the group accidentally excluded depth parameters from its loop, the test would still pass via path (a). Task 1.3 requires "modulation-depth child targets refresh through the recursive compute path," so path (a) is the intended mechanism — but the test can't distinguish the two. This doesn't break anything today; it just means a future regression where depth parameters are dropped from the loop would go undetected by this test.
