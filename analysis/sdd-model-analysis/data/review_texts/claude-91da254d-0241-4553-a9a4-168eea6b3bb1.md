### Verified correct

**Alpha/premultiplication math (matched across backends).** Both sides compute effective alpha as rounded `(mask * color.a + 127) / 255` integer division — `ui.ts:363` and `PortableJuceBackend.hpp:207-208`. Both write *straight* (non-premultiplied) RGBA and rely on the compositor for source-over: browser via `putImageData` into an offscreen canvas (`ui.ts:355-364`, ImageData is spec-straight) then `drawImage`; JUCE via `setPixelColour(juce::Colour(...))` which premultiplies on store into the ARGB image, then `drawImage`. Straight-alpha semantics are consistent and correct on both.

**Canvas state restoration even on throw.** `drawAlphaRaster` validates and fills the offscreen *before* touching the destination context; the only destination mutations (`globalAlpha`/`globalCompositeOperation`/`imageSmoothingEnabled`/`drawImage`) sit inside `try { … } finally { context.restore() }` after `context.save()` (`ui.ts:365-374`). Validation-before-mutation means a malformed command leaves the destination untouched. JUCE uses `ScopedSaveState` (`PortableJuceBackend.hpp:221`). Both verified by tests.

**Offscreen reuse/lifetime and resize resets.** Offscreen canvas/context are lazily created once and reused; on dimension change the canvas is resized and `rasterImageData` is invalidated (`ui.ts:340-352`). Every pixel is rewritten each frame (`alpha.length === rasterWidth*rasterHeight`, guaranteed by `validateAlphaRaster` byte-count check), so no stale-pixel bleed on reuse. Test 2 confirms same-source reuse across two draws and zero destination `putImageData`.

**Destination `putImageData` avoidance / dispatch.** `AlphaRaster` is intercepted before the shape `switch` and returns (`ui.ts:301-305`), so it never falls through to rect/polygon drawing; `putImageData` only ever targets the offscreen (test asserts `destinationPuts === 0`, `offscreenPuts === 2`).

**Nearest-neighbor semantics match.** Browser `imageSmoothingEnabled = false` ↔ JUCE `lowResamplingQuality` (JUCE's nearest-neighbour tier; bilinear is medium). Consistent.

**Bounds/no-op guards.** Non-positive target extent is a no-op on both (`ui.ts:339`, `PortableJuceBackend.hpp:190-193`), tested on the JUCE side.

**Tests compare real output.** Browser test 1 drives full `renderFrame` (decode → draw) and reads back real canvas pixels against an independently derived composite (incl. source-over overlap). JUCE test drives `PaintDrawCommand` and probes pixels, and cleverly verifies opacity/resampling restoration by comparing a post-raster probe draw against a never-touched reference `Graphics`.
