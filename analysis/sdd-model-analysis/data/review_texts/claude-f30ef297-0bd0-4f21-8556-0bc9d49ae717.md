**2.3 — Shell hosts portable surface; ordering preserved** ✓
- `Runtime::AppSurface()` returns `engine_.Application().PortableSurface()` (Runtime.hpp:291), replacing the old `AppComponent()`. Satisfies sar-10/sar-17.
- `MainPane` owns `synth_juce::PortableComponent appComponent_`, constructs it from `runtime.AppSurface()`, and toggles visibility (never destroys) across page navigation — sru-1 "Default view is the application" / "Page opens and returns."
- Repaint ordering preserved: `ShellComponent::RepaintAll` → `RefreshOnTick` (calls `appComponent_.RefreshFromSurface()`) → `mainPane_.repaint()`. Refresh precedes repaint (plan Step 3). Backend consumes the tree and dispatches actions; it never touches the parameter manager — sar-10 "Repaint reads UI-state atomics."
- Action routing matches the `Surface` contract: backend controls call `DispatchAction` (authoritative), and `SetActionHandler` is registered only as an optional observer forwarding to `m_outerActionHandler` — consistent with the PortableUI.hpp comment that the handler "must not duplicate the surface's own action routing." `PortableJuceBackendTests.cpp` confirms one dispatch per click.

Backend test builds/passes; miniapp geometry + system tests pass (verified by controller). App-facing headers stay JUCE-free (Task 2), hosted through the backend.

### Non-blocking observations (not Task 3 fixes)

1. **Rows/Sections/ScrollAreas not yet rendered.** The backend iterates only `root->children` one level deep and skips non-interactive/non-draw kinds. sru-12 lists rows/sections/scroll areas, but the plan explicitly scopes Task 3's first backend to the listed controls + draw nodes, and the miniapp surface is flat. This is correctly deferred to Task 5 (runtime pages) — flagging so it's on the radar there.

2. **`MiniAppJuceSurface.hpp` not created.** The plan lists it conditionally ("if the generic backend needs widget-specific paint behavior"). The generic `PaintDrawCommand` handles draw nodes without it, so its absence is correct.

3. **ComboBox `onChange` captures `node` by value** (PortableJuceBackend.hpp:524). On reconcile the control is reused but the lambda retains the original `node.options`, so if options change the dispatched id could go stale. Miniapp combos are static, so no impact now — worth hardening when Task 5/6 introduce dynamic option lists.

4. **Per-tick `setValue`/`RefreshFromSurface` parity risk.** Sliders get `setValue(node.value, dontSendNotification)` every tick; `m_suppressActionDispatch` prevents an action feedback loop, but a live drag could visually fight the tick until the round-trip (action → uiBus → param → BuildTree) settles. Worth confirming in the Task 7 manual smoke that gesture/blend sliders feel smooth.
