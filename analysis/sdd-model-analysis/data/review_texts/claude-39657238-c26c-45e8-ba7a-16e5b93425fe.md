**Observation A — edit-path collision with hidden orphan pressure is safely refused (verified, not a bug).**
The `AddSingle`/`AddBlock` paths skip physical addresses owned by hidden orphan pressure mappings (`NextFreeWrldBldrGridPosition`/`NextFreeLaunchpadGridPair`, `src/MidiConfigViewModel.cpp:2814,2826`). The *edit* path has no such pre-skip, so a grid-cell edit could in principle land a derived pressure address onto an externally-authored orphan's address. I traced this to the flush terminus: `FlushSectionPresentationToSlot` ends with `SlotValidForKind` (`MidiConfigViewModel.cpp:1980`), which calls `PolyphonicPressureConfigError` and rejects duplicate pressure addresses; the slot is a scratch copy committed to `out` only on success, so the commit is refused atomically with a reason. This satisfies `sru-26` "Pair edit is atomic … duplicate address … refused." Covered by `GridInvalidRectangleAndDuplicatePairEditsRefuseAtomically`.

**Observation B — greedy rectangle coalescing is width-first (verified correct for the contract).**
`ReconstructGridMappings` (`MidiConfigBlocks.cpp:823`) grows width then height. This is deterministic and round-trip-exact (expanding the reconstructed block reproduces the exact cells), and it recovers any fully-rectangular authored run as one maximal block — which is what `sru-26`/`sru-27` require. Not a defect.

**Observation C — `CreateGrid`/`CreateSlot` return `optional<size_t>` but never yield `nullopt`.** Invalid ranges are rejected earlier at `GridRange::Create` (an invalid range is unrepresentable), so these APIs only ever throw on post-finalization mutation. Minor vestigial API shape; no behavioral impact. `bgr-1` "invalid range rejected atomically" is honored at the range constructor and tested.
