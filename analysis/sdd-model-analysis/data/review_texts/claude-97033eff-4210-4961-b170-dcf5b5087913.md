**2. `tsconfig.json`'s `"files"` list silently limits the build to one file (`projects/synth/browser/tsconfig.json:12`)**
`"files": ["playwright.config.mjs"]` overrides TS's default whole-directory inclusion, so `tsc -p tsconfig.json` compiles *only* that config file — confirmed: `dist/` contains solely `playwright.config.mjs`, nothing else. This wasn't asked for in the brief (which only specified `rootDir`/`outDir`/ES2022). Consequence: `npm run build` currently does no real type-checking, and any `src/*.ts` added in a later task won't be picked up unless this file is edited again — "TypeScript build passes" is a much weaker gate than it appears.

Related: `public/index.html:4` already references `../dist/src/main.js`, but no `src/main.ts`/`main.js` exists in the repo — that script tag 404s today. Likely intentional deferral to a later task, but combined with finding 2 it means the static site currently has no working entry point and the build wouldn't catch that if one were added incorrectly.

**3. Generated build output isn't gitignored**
`.gitignore` has per-project `dist/` entries for conductor/xagent/sheaf-chat but none for `projects/synth/browser/dist/` or for this Makefile's `wasm-build/` output dir (`projects/synth/browser/Makefile:4`). This is already visibly manifesting: `git status` at the start of this session shows `?? projects/synth/browser/dist/` untracked. A later `git add -A`/`git add .` in this area will pick up generated artifacts.

The report states native compilation "prov[es] both generic entry points are portable C++ translation units," but only ran `make -n` (dry-run) for the real `em++`/`STANDALONE_WASM` targets. `synth_miniapp::MiniApp` → `MiniAppCore.hpp` → `include/synth/MidiController.hpp:7,286` pulls in `<thread>`/`std::thread thread_`, which needs `-pthread` under Emscripten and isn't supported by default with `-sSTANDALONE_WASM` (`projects/synth/browser/Makefile:23-24`). Native-compiler success says nothing about that. This means the global constraint "build must fail or implementation must stop if a concrete app cannot run without app-specific browser runtime/backend code" has not actually been exercised for the real miniapp — it's a disclosed gap (report's own Concerns section flags `em++` isn't installed), but the Verification section's wording claims more certainty than was established.
