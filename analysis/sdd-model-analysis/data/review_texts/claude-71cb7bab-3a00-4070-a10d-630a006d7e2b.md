## Findings

### Important

**I-1 — `tasks.md` badly understates completion (OpenSpec artifact accuracy).**
`openspec/changes/add-sheaf-synth-superapp/tasks.md` marks only **1.1** and **3.1** checked, yet the code for **1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 3.2, 3.3, 3.4, 4.1, 4.2, 4.3, 4.4, 4.5** is all present and appears complete (registration helper `AppRegistry.hpp:69`; miniapp registration `MiniAppRegistration.hpp:10-23`; concept/id tests `contract_tests.cpp:106-159, 284-338`; launch helper `Shell.hpp:77-110`; path injection test `RuntimeShellSessionTests.cpp`; resolver `AppRegistry.hpp:55`; sheaf-synth target `apps/sheaf-synth/Makefile` + root `Makefile:154-159`; UI harness `LauncherHarnessTests.cpp`). These should be checked off. This is the kind of spec-vs-reality drift the OpenSpec-first workflow exists to prevent — recommend the implementer reconcile after running verification.

**I-2 — Task 3.5 persistence-behavior tests are genuinely missing (correctly left unchecked).**
Spec spp-10 has two behavioral scenarios with no test backing:
- *"Startup loads only selected app patches / patches saved for other registered apps are ignored"* — isolation is only **structural** (each app roots its `PatchBrowser` at `patches/<appId>`). No test creates `patches/appA` + `patches/appB` and proves an app started for `appB` ignores `appA`. Confirmed absent via grep.
- *"config document contains runtime configuration only, not patch parameter values"* — no save→file round-trip asserts this.

All current spp-10 coverage (`contract_tests.cpp:94-133`) is **path-string construction**, not persistence behavior. 3.5 should stay unchecked until these are added.

### Advisory

**A-1 — `SynthAppRegistration` invariant is only enforced by the factory, not the type.** The struct is aggregate-constructible directly, bypassing `IsValidSynthAppId`/the `SynthApplication` concept — which is exactly what `LauncherHarnessTests.cpp:22-33` and `contract_tests.cpp:114-125` do. Task 1.4's "registered app ids are non-empty/path-safe" holds only on the `Make*` path. Fine for in-tree use; worth a comment noting direct construction is test-only.

**A-2 — Weak harness assertions.** `LauncherHarnessTests.cpp:53` (`contains("2")`) and `:69` (`contains("Sheaf")`) can match substrings of unrelated fields; consider asserting the full formatted row or exact field. Non-blocking.

**A-3 — No negative-compile test for sar-20 "missing app contract caught at build time."** The concept requirement exists (`AppRegistry.hpp:69`, `AppConcepts.hpp:20-22`) and `contract_tests.cpp:284-293` proves gating, but nothing asserts a bad type *fails to compile*. Acceptable (hard to unit-test in one TU); noting for completeness.

**A-4 — Config filename asymmetry.** Sheaf-launched config is `…/config` (no extension, `AppRegistry.hpp:66`) while standalone is `config.json` (`AppContext.hpp:48`). This is intentional and matches the spec's literal `data/synth/sheaf-synth/config`, but a one-line comment would prevent future confusion.
