## Audit summary

**Raw-pointer lifetime / view pins.** The only production holders of local `Parameter*` are the parent's `modulationDepths_[]` (cleared on detach, `ParameterModulation.cpp:848`) and `Bank::visible_`/`selected_`. Pins are established exactly once per visible local in `OpenModulationView` (`:2374`,`:2380`) and released exactly once in `Deselect` (`:2236`,`:2239`) and in the `OpenModulationView` transition prologue (`:2367`,`:2370`). I traced pin balance across plain open, nested deepen, and cross-target transitions — all balanced; the top-level target's pin is a no-op (`PinLocalForView` guards on `kLocalParameterId`, `:797`). The three other `visible_ = topLevel_` sites (`:2105`,`:2113`,`:2167`) are all guarded by `!ShowingModulation()`, so no pins are ever dropped silently. Recycled objects are reused, never freed, so even a retained pointer is never dangling memory; the design's "topology-lifetime" contract holds.

**Collecting a neutral child while the parent route settles (the flagged case).** Detach only clears `modulationDepths_[sourceIx]`; the settling depth state lives in the *parent's* `currentDepths_`/`targetDepths_` (`ComputeAtDepth` `:1790-1809`), where `currentNonNeutral` keeps the route active with `target=0` even when the child pointer is null. `CanRecycleLocal` itself requires `activeRouteCount_ == 0` on the *child* (`:815`), which is orthogonal. Confirmed safe and directly covered by `neutral_local_collection_detaches_child_while_parent_route_finishes_settling`.

**Stale pointer across a collection boundary.** Collection is invoked only at `Deselect` (`:2244`), `ApplyModifierToParameter`/Reset (`:2415`), `RevertAllToDefaults` (`:2740`), and `LoadPatchJSON` (`PatchPersistence.cpp:296`) — never from `ProcessSample`/`ProcessLite`/`GetRaw`/`ComputeAtDepth`/modulation application (verified by grep). Any parameter being edited at these boundaries is either top-level (never recycled) or a pinned visible local; pinning protects it under *any* collection trigger, not just deselect. No caller dereferences a collected pointer.

**Accounting / high-water / index semantics.** `parameterCount_` is never decremented; `storageLocalIx_ = group.parameterCount_` at construction matches `ParameterByLocalIndex` enumeration order (initial storage then batches in fill order). `AvailableParameterSlots` sums never-used initial + never-used batch + recycled slots with no double-count (recycled slots were already `allocated`). Reuse validates backing batch pointer, `slotIx_`, `storageLocalIx_`, live identity via `ParameterByLocalIndex`, and batch `Compatible` before reset (`:483-489`). Recycled slots are consumed only for `kLocalParameterId` creation (`:480`), so a later root registration cannot repurpose one. `ResetLocalForReuse` (`:855`) covers **every** `Parameter` member field enumerated in the header (`ParameterModulation.hpp:515-546`) except the correctly-preserved storage identity (`storageBatch_`/`slotIx_`/`storageLocalIx_`), and allocates nothing.

**JSON preservation.** A parent serializes a child only when `child->HasNonDefaultState()` (`:1087`). Eligibility requires `!HasNonDefaultState()` (plus more), so a collected node contributed nothing to JSON — collection cannot alter value JSON. Gestures 32/63 and nested non-default routes are retained; `patch_load_collection_preserves_high_gesture_nested_state_and_collects_default_omissions` and `eligible_collection_preserves_semantic_parameter_json` cover this with key-order-independent comparison.

**Test adequacy.** Every retention reason, recursive collapse, settling detach, pin boundary, revert boundary, distinct-parent reuse, beyond-capacity boundedness, randomized reuse, semantic JSON, and lazy rematerialization with full metadata reset are covered.

I could not find any Critical or Important defect. Minor observations below do not affect correctness.

## Findings

**Minor 1 — redundant whole-group collection under reset-all.** `Bank::ApplyModifierToParameter` (`ParameterModulation.cpp:2415`) collects the entire group on every `Reset`. When driven by `ApplyModifierToTopLevel` (`:2216`, loops over all top-level cells), this performs O(top-level) full-group collection passes instead of one. Control-path only; correctness is unaffected.

**Minor 2 — recycling is implicitly limited to standard 0.5/Bipolar depth defaults.** `HasNonZeroState` uses a hardcoded `neutralDepthCenter = 0.5f` (`:1924`). Production locals are always built by `ModulationDepthConfig` (`defaultValue = 0.5f`, `RangeKind::Bipolar`, `:1416`), so this is correct today. But a local materialized through the public `EnsureModulationDepth(modIx, config)` overload with a different default would sit at its own default yet be treated as "non-zero," so it would never be recycled (slot retained until group teardown). Safe (conservative), but the coupling is undocumented and worth a comment.

**Minor 3 — no direct test of multi-level nested-view pin balance.** Pins are tested for a single open→deselect (`modulation_view_pins_visible_locals_until_deselect_boundary`) and the duplicate-name reopen test, but there is no test that opens a view, deepens into a nested child view, then unwinds, asserting `UnpinLocalForView` underflow never triggers. The logic is correct on inspection; this is a coverage gap only.
