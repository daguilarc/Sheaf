### Findings

**[Important] Delegating default constructor is not `explicit`, breaking API equivalence with the specified single-constructor signature**
`projects/synth/include/synth/DspLogStructuredBuffer.hpp:135-136`
```cpp
LogStructuredAudioBuffer()
    : LogStructuredAudioBuffer(Config{}) {}
```
The interface pinned by the plan/OpenSpec is a single constructor: `explicit LogStructuredAudioBuffer(Config config = {});`. I confirmed by compiling a minimal repro that Clang genuinely rejects that exact single-constructor form here (`default member initializer ... needed within definition of enclosing class ... outside of member functions`), so splitting into two constructors is a legitimate workaround — the report's caveat is accurate and not just cover for laziness. However, the zero-arg constructor was left non-`explicit`. I verified this measurably widens the API surface versus the spec'd single explicit constructor: `LogStructuredAudioBuffer a = {};` and `f({})` (for a function taking `LogStructuredAudioBuffer` by value) both compile with the current code, whereas they must be rejected under `explicit LogStructuredAudioBuffer(Config config = {})`.
**Fix:** mark the delegating constructor `explicit` too:
```cpp
explicit LogStructuredAudioBuffer()
    : LogStructuredAudioBuffer(Config{}) {}
```
I confirmed this one-line change restores full explicit-only semantics (`a = {}` now correctly fails to compile) while keeping `LogStructuredAudioBuffer buffer;` and designated-initializer construction working, i.e. it closes the gap with zero cost to the two legitimate use cases the report calls out.
