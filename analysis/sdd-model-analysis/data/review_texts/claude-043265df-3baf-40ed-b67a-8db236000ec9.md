### Minor

**M1 — Epoch is allocated outside the route guard; correctness relies on an undocumented single-writer-per-route assumption.** `projects/synth/src/MidiController.cpp:489-490` allocates the epoch (`AllocateEpoch()`) *before* acquiring the per-route guard (`GuardRoute(route)`). If two threads ever `BeginInput` the *same* route concurrently, the later-allocated epoch could be published first and then overwritten by the earlier one, leaving the route's "latest expectation" epoch lower than an epoch already handed to a live event — a genuine causal-staleness bug. It is **not reachable** under the spec's threading model: a route key is `(controllerSlot, parameterSlot, position)`, so one route belongs to exactly one controller/device, and MIDI input callbacks are per-device and serialized (design §1, sar-7). Multiple controllers sharing a cell get distinct `controllerSlot`s and therefore distinct records. The guard's stated job (design §1) is input-vs-output linearizability, which holds. Recommend documenting the single-writer-per-route invariant with a comment or `assert`, since the guarded section does not itself make epoch-allocate-then-publish atomic. Uncertainty: low that this is exploitable; flagged for durability against future threading changes.

**M2 — `BeginInput` can consume an epoch it never publishes.** `MidiController.cpp:489` allocates before the `guard.IsTracked()` re-check at :491. For a tracked-but-unoccupied reservation the epoch is allocated then discarded. Harmless (epochs only need to be increasing and nonzero, which is preserved) and unreachable via `Process` (which returns on `!route.IsTracked()` before calling `BeginInput`). Purely a wasted-epoch nicety; noting for completeness.

**M3 — `assert(alert.IsPublished())` is the only guard against a silent epoch-0 downgrade.** `MidiController.cpp:572`: in release builds the assert compiles out, and if `BeginInput` ever returned unpublished, `alert.Epoch()` yields `0` and the code pushes an untracked `ParamSetAbsolute`. Given reservation guarantees `occupied`, this is currently unreachable, so it's a robustness note, not a defect.

**M4 — `routes_` is a ~230 KB inline `std::array` (4096 records).** Fine for the engine-owned production instance and acceptable in tests, but every stack-local `AbsoluteFeedbackCoordinator` in the test file materializes it on the stack. No action needed; noted as an observation.
