## Findings

### Architecture & Correctness — verified sound
- **`Bank::EnsureModulationDepthParameter` (`ParameterModulation.cpp:2337–2350`)**: the `connected` guard is placed *before* the `ModulationDepthParameter(modIx)` lookup, so an explicitly/legacy-assigned depth at a disconnected index is correctly hidden while the underlying parameter object is left intact. Matches spm-75 "Explicit disconnected depth remains hidden." Only two callers exist (`OpenModulationView`, `RandomizeModulationDepths`), both UI-driven — no DSP/route path regresses.
- **`MissingModulationDepthCount` (`:2356–2365`)** and **`OpenModulationView` (`:2377–2412`)** use the identical connected-only predicate for preflight and materialization, keeping the open atomic. Disconnected indexes still get a fixed-position null cell (`:2402–2405`); the return cell stays at `physicalLayout.back()`. Physical topology preserved.
- **`RandomizeModulationDepths` (`:2435–2467`)**: allocation-free `count_if`, early-return on zero connected, and an ordinal→index scan over `Metadata()` in configured order. `NextRandomIndex` normalizes all custom sources with `% exclusiveMax` (`:3049`), so `ordinal ∈ [0, connectedCount)` and the scan can never fall through to an out-of-bounds `Metadata(size())`. Bounds/lifetime safe.
- **`ModulatorMetadata.connected` defaults to `false`** (`ParameterModulation.hpp:212`); registration paths (Braid4Core, Modules, StandardModulators) set `true` per source. No previously-connected source silently became disconnected; topology is fixed by registration.
- **Braid4UI.hpp (`:58–68`)**: the `continue` only fires under `showingModulationView && !state.connected`; top-level rendering is unchanged, connected app-source cells (encoder-only, e.g. 4/5) still draw, and no side-effect-bearing statements are skipped. Both relaxed reads are index-guarded (no OOB under a torn read).

The two apps legitimately differ; only Braid4's aesthetic requires node suppression. No fix required — optionally reconcile the design doc's generic wording.
