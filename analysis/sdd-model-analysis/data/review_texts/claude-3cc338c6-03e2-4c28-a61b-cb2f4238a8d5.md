## Findings

### Minor

**M1 — `Config()` reference can outlive the freeze gate.** `projects/synth/include/synth/StandardModulators.hpp:64` returns a mutable `Configuration&`. The freeze only rejects *new* calls after `registered_`; a caller that captures `auto& cfg = bundle.Config()` before `Register()` can still mutate frozen fields afterward, bypassing the ssm-2 "configuration freezes after registration" guarantee. Not reachable through the app code here (single-threaded init-time config), so it is defensive hardening only, not a live bug.

**M2 — Dead constant work in the monophonic specialization.** In `Register()` (`StandardModulators.hpp:119-132`) `connectedConstantMetadata` is built and `constantVisualizer_.SetColor(...)` is applied unconditionally, even though the constant source is never installed for `VoiceCount==1` (the `if constexpr (VoiceCount > 1)` guard at line 143). Harmless and cheap; could be moved inside the guard for clarity.

**M3 — Braid4 p99 deadline is scheduler-sensitive with real prior misses.** Honestly disclosed in the Task 4/5 reports: the original Task 4 commit produced one 96 kHz p99 of 3.592 ms (over the unchanged 2.133 ms limit), and one 48 kHz outlier of 4.6 ms in a final-verification attempt. Both resolved after the private-friend unchecked sparse dot-product fix; the final Task 5 pass and four serial post-fix passes are clean (96 kHz p99 1.499–1.554 ms, ~30% headroom) with **no threshold or workload relaxation** (`braid4_deadline_tests.cpp` still asserts `≤0.60`/`≤0.80`). Real-but-managed residual risk for a hard-real-time callback; margin exists across many independent passes. Worth continued monitoring, not a blocker.
