### Minor

1. **Test-only seams compiled into the production API** — `MidiSender::GuardQueueForTests()` (`MidiController.hpp:370`) hands out the sender's internal `mutex_` to any caller, and `AbsoluteFeedbackCoordinator::RouteGuardHeldForTests()` (`MidiController.hpp:170`) plus the public `GuardRoute`/`Snapshot` widen the coordinator surface. They add no work to hot paths (confirmed) and the report justifies them as the only way to make the linearizability interleaving deterministic, but they are permanently public. Consider `friend`-scoping or a test-only header in a follow-up. Not blocking.

2. **Non-atomic `occupied` read outside the reservation guard** — `GuardRoute`/`RouteGuardHeldForTests` read `routes_[i].occupied` (`MidiController.hpp:177`, a plain `bool`) without the `reservationGuard_`, while `ReserveRoute` writes it under that guard. The field is write-once-before-first-use and the processor-swap synchronization supplies the needed happens-before in practice, so this is benign, but a strict ThreadSanitizer run could flag the pair. Making `occupied` an `std::atomic<bool>` (or folding it into the guarded region) would remove the ambiguity. Not blocking.

3. **TDD-process disclosure (Task 5), not a code defect** — two added behavioral tests (`rig_absolute_feedback_resolves_only_latest_same_route_rapid_input`, `tracked_absolute_output_beyond_visible_capacity_stays_safely_gated_while_pending`) passed against the pre-cleanup implementation, so there was no honest RED; they close integration/policy coverage rather than repair an observable failure. The report is transparent about this and did not manufacture a fake RED. The unrelated `braid4…deadline` p99 miss was a host-timing flake that passed on exact and full reruns. Neither affects correctness of this change. Noted for the record only.

4. **Added per-cell `ComputeRawCenter` on the UI-publication path** — `PopulateUIState` now calls `ComputeRawCenter(scene)` per visible connected cell (`ParameterModulation.cpp:1253`) in addition to the existing display computation. It is allocation-free and runs only at the throttled control cadence, so it is within the realtime contract, but it is net-new audio-thread work worth keeping in mind if publication cadence is ever raised. Not blocking.
