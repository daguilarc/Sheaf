## Characteristic behaviors

- **Always opens with a mapping pass, never opens with code.** Every session's Turn 1–2 is "read the brief, then map existing conventions/interfaces/test harness before touching owned files" (task-1 turns 1–2; task-2 turns 1–2; task-4 turn 1; task-5 turn 1; task-6 turns 1–2; button-grids task-2 turn 1). It treats the supplied task brief as an already-approved design boundary rather than re-deriving requirements, which keeps this phase short (1–2 turns) instead of turning into open-ended exploration.

- **Genuine red-first TDD, including mid-stream new red tests for edge cases it discovers itself.** task-1: writes the contract test, confirms an actual RED run (turn 3–4) before adding any implementation. task-2 goes further: after first GREEN it notices an uncovered edge case (unsupported draw kind hitting an internal invariant instead of the diagnostic path), writes a *second* failing test for it (turn 5), confirms it fails for the right reason (turn 6), then fixes forward. task-4 and task-5 both explicitly build a red Playwright/C++ scaffold before any runtime code exists, and tighten the test itself when it notices the test harness (not the production code) is the source of a red result (task-4 turn 4: "I also found one assertion that Playwright doesn't provide, so I'm tightening the test itself"). Tests and code are not written together — the red run is always observed as a real command output before implementation begins.

- **Ends every session with a pre-commit ritual: full suite + focused target + `git diff --check`, re-run fresh, immediately before staging.** This is identical across all 8 sessions regardless of grade: task-1 turns 20–21, task-2 turns 9–10, task-4 turn 17 ("I'm doing the last diff/self-review pass, then... commit only the task files"), task-5 turns 14–16, button-grids task-2 turns 10–11, task-8 turns 6/9/12/16. It also consistently stages an explicit, narrow file list and narrates which untracked/owned-by-others files it is deliberately leaving out of the commit.

- **A real self-review step that catches its own bugs before reporting, not just before committing.** task-2 turn 8 self-review flags that the test only checks aggregate draw-kind count, not per-kind mapping, and tightens it. task-4 turn 16 self-review finds a lifecycle gap (worker still accepts `load` after `destroy`) and fixes it; turn 18 self-review finds a member-initialization-order/lifetime bug in the C++ wrapper and reorders fields — both found by re-reading its own diff, not by an external reviewer. task-5 turn 13 self-review adds a missing assertion (block-size vs callback-size confusion) before the final run. This self-catch behavior appears in the B/A-graded sessions; it's less prominent in the sessions that scored lower.

- **Effort=high sessions show materially deeper, more compounding reasoning per turn than effort=medium.** Medium-effort turns (task-1, task-2, button-grids task-3, task-8) mostly stay under ~300–500 reasoning tokens with a single SAY/THINK bullet per turn. High-effort turns (task-4, task-5, button-grids task-2) repeatedly stack 3–6 THINK bullet blocks within one turn and spike to 900–2300 reasoning tokens (task-4 turn 6: 2182 reasoning tokens across 4 stacked THINK blocks; task-5 turn 6: 2316 reasoning tokens across 6 stacked blocks; button-grids task-2 turn 3: 1468 reasoning tokens). This looks like effort=high genuinely running longer internal deliberation chains per turn rather than just producing more output.

- **Environment breakage is worked around locally rather than escalated, repeatedly.** task-1 hits a Makefile `build`-target collision (renames the directory var), a root-owned `~/.npm` cache (redirects to a task-local cache under `/private/tmp`), and a TypeScript "empty files list" plus transitive Playwright type errors (adds `allowJs`/`skipLibCheck`) — all self-remediated in-session rather than flagged as broken infrastructure. task-4/task-5/task-8 hit a sandboxed-Chromium Mach-port restriction under Playwright and route around it by requesting elevated/host execution permission rather than stopping. Every one of these is small and locally fixable, but the pattern is consistently "diagnose and patch around it" rather than "stop and escalate," which cuts against a stop-and-escalate norm for genuinely broken infra.

- **Does stop cleanly at a real ownership/design boundary, but the resulting BLOCKED report was short and the subsequent unblock still shipped a WASM-specific bug.** task-6 (F grade) is only 6 turns: it maps the ABI, confirms `RuntimeAbi` has no MIDI-capable export surface, treats that as the explicit "stop and report BLOCKED" condition from its own prompt, and writes the blocked report with a concrete minimal-unblocker recommendation — a disciplined, non-thrashing stop. But the grade file shows the eventual fix (in a later session) started a real `std::thread` in `MidiSender` with no WASM pthread flags, and the C++ tests only passed because the *native* build used a real thread — the WASM path was structurally untested since `em++` is unavailable in-sandbox. This mirrors a blind spot visible across several sessions (task-1, task-4, task-5, task-6): "native compilation succeeds" / "clang++ compiles cleanly" is repeatedly reported as verification evidence for code whose actual target is WASM, which is a systematic false-confidence gap this model doesn't compensate for.

- **Multi-agent contention on a shared worktree produces real churn, not self-inflicted loops.** task-4 (B grade, high effort) spends roughly 9 turns (21–29) discovering and reconciling concurrent edits from other workers touching the same files: it detects another agent's `BrowserAppEntry.hpp` factory mid-task (turn 21), redesigns around it, later finds another worker already created "the" commit on the shared branch and chooses to amend rather than duplicate (turn 24), then absorbs a second concurrent report update (turn 28) and a controller follow-up commit (turn 29) before finishing. None of this is the model looping on its own mistake — it's overhead imposed by shared-worktree concurrency — but it roughly doubles the turn count of an otherwise ~17-turn task.

## Per-session notes

**add-browser-wasm-runtime__task-6 (high, F).** Shortest session read (6 turns). Maps the MIDI-reconcile core and the existing WASM ABI, confirms via the brief's own "stop and report BLOCKED" clause that the ABI can't express inbound/outbound MIDI without expanding scope, and stops cleanly with a concrete unblocker rather than forcing a workaround. The discipline to stop is good, but the eventual F grade (from a later continuation session not covered by this transcript) traces to a critical bug — a `std::thread`-based `MidiSender` with no WASM pthread flags — that a native-only compile check could never have caught, consistent with the "native compile as proxy for WASM correctness" gap seen elsewhere.

**add-browser-wasm-runtime__task-1 (medium, C).** 24 turns, the most infrastructure-fighting of the eight: a Makefile target collision, a root-owned npm cache, and TypeScript config quirks (empty `files`, transitive lib-check failures) are each diagnosed and patched around in-session rather than escalated. TDD is real (explicit RED confirmed in turn 4 before any implementation). Ends with a careful scope/diff review and narrow staging, but needed a sandboxed git-index-lock permission escalation just to commit (turn 22).

**add-browser-wasm-runtime__task-5 (high, C).** 19 turns.
