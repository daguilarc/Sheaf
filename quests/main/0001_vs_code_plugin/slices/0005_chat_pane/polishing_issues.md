## Issue POL-0001

- title: Session and command failures do not consistently create chat error bubbles
- details: The spec requires the chat pane to show errors that affect the session or a user-visible command outcome, and the slice plan specifically calls for error bubbles for incoming `error` events and session-fatal failures. The current implementation only records incoming realtime `error` events in `ChatModel.ingestEvent()` and start failures in `SessionController.StartSession()`. Other user-visible failure paths are logged or shown outside the chat pane without a `ChatModel.recordError(...)` call: `CommitAndRespond()` catches `commitAudioAndCreateResponse()` failures and only logs them (`apps/vscode-extension/src/sessionController.ts:124`), microphone capture `onError` shows a VS Code error and stops the session with `audio_error` but only leaves a generic session-ended context bubble (`apps/vscode-extension/src/sessionController.ts:248`), and `connection_lost` is shown via VS Code error message after `onSessionEnded` has reset the chat model to a context bubble (`apps/vscode-extension/src/sessionController.ts:208`, `apps/vscode-extension/src/sessionController.ts:300`). This means the focused chat pane can miss exactly the failure context the user needs when a session or command fails.

  Re-check after the 2026-05-23T22:25:00Z `Fixed` response: the commit failure path now records `Commit failed: <message>`, and the `connection_lost` path now records an error after `onSessionEnded` resets the model. The microphone failure path is still not fixed for the real session ordering. `onError` records `Microphone error: <message>` before calling `StopSession("audio_error")` (`apps/vscode-extension/src/sessionController.ts:250`), but `StopSession()` calls `session.stop(...)`, and the real realtime-agent `stop()` invokes `onSessionEnded`; this callback calls `this.m_chatModel?.reset(info.reason)` (`apps/vscode-extension/src/sessionController.ts:210`), clearing the microphone error bubble and replacing it with only the session-ended context bubble. The added microphone test does not catch this because its fake session's `stop()` callback only records the reason and does not invoke the captured `onSessionEnded` callback like the real session does.

  To mark this issue `completed`, session-fatal failures and user-visible command failures must produce durable `error` bubbles in the chat model without losing the existing session-ended context behavior. Commit rejection and unexpected connection loss appear covered; microphone capture failure still must be adjusted so the error remains after the `audio_error` session stop/reset sequence. The microphone test must model the real `stop()` -> `onSessionEnded` ordering, or otherwise assert the final post-stop `ChatModel` snapshot contains both the session-ended context and the microphone error.
- resolution_notes: Verified the follow-up fix. `CommitAndRespond()` records commit failures as chat error bubbles, `HandleSessionEndedUnexpectedly("connection_lost")` records an error after the session reset, and microphone capture `onError` now waits for `StopSession("audio_error")` to complete before appending the microphone error bubble. The microphone regression test now simulates the real `stop()` -> `onSessionEnded` ordering and asserts the final chat snapshot contains both a session-ended context bubble and the microphone error bubble. No open issue remains.
