## Why

OpenSpec and Superpowers are currently installed through each harness's own
global channel (npm global for the OpenSpec CLI; marketplace/plugin installs for
Superpowers). That splits ownership from `projects/agents`, drifts across
Claude/Cursor/Pi/Codex, and makes the agents installer incomplete: it already
owns shared skills, but not these two critical toolchains. Vendoring both under
`projects/agents/vendor/` and installing from that source closes the gap.

## What Changes

- Add vendored source trees at `projects/agents/vendor/openspec` and
  `projects/agents/vendor/superpowers`, pinned to explicit upstream revisions.
- Extend the agents installer so install/check/clean (repo and global scopes as
  appropriate) distribute OpenSpec and Superpowers artifacts into the four
  harnesses the same way shared skills are managed today — managed markers,
  conflict safety, drift detection, and obsolete cleanup.
- Install the OpenSpec CLI from the vendored package so agents do not depend on
  a global `npm install -g @fission-ai/openspec`.
- Install Superpowers as managed local plugin/package installs from the
  vendored tree for Claude, Cursor, Pi, and Codex so the `superpowers:` skill
  namespace and hooks keep working without marketplace or `pi install git:…`
  setup.
- Document that after this lands, global OpenSpec npm installs and Superpowers
  marketplace/plugin installs are obsolete for Sheaf agent work.
- Update `projects/agents` README / Make targets as needed for vendor sync and
  install.

Research note (install surfaces today):

- **OpenSpec** ships a real Node CLI (`@fission-ai/openspec` → `openspec`).
  Harness skills/commands are generated by `openspec init` / `openspec update`
  into paths like `.claude/skills/openspec-*`, `.cursor/commands/opsx-*`,
  `.pi/prompts/opsx-*`, and `.codex/skills/openspec-*`.
- **Superpowers** does **not** ship a standalone CLI `bin` today; it is a
  skills + harness-plugin package (Claude/Cursor/Codex plugins, Pi package
  extension, shared `skills/`). The agents installer becomes the install
  surface in place of marketplace/`pi install` flows.

## Capabilities

### New Capabilities

- `agents-vendored-tooling`: Vendored OpenSpec and Superpowers source trees under
  `projects/agents/vendor/`, revision pinning/update flow, OpenSpec CLI install
  from vendor, and Superpowers/OpenSpec harness artifact install from vendor
  into Claude, Cursor, Pi, and Codex.

### Modified Capabilities

- `agents-skill-distribution`: Agents installer/Make entry points incorporate
  vendored OpenSpec and Superpowers install/check/clean alongside existing
  skill and instruction outputs, without treating marketplace/npm-global
  installs as the source of truth.

## Impact

- `projects/agents/vendor/` (new)
- `projects/agents/scripts/install.py` and tests
- `projects/agents/Makefile`, root Makefile agents targets as needed
- `projects/agents/README.md`
- Repo-local OpenSpec skills/commands for Claude, Cursor, Pi, and Codex
- User-global managed Superpowers plugin/package installs for those four
  harnesses
- Managed OpenSpec CLI location (no global npm dependency for Sheaf agents)
- Offline-capable vendor trees under `projects/agents/vendor/` (OpenSpec
  includes resolved `node_modules`)
- Existing repo files previously produced by `openspec update` become
  agents-installer-managed outputs sourced from vendor in the landing commit
- Developers who currently rely on `npm i -g @fission-ai/openspec` or
  Superpowers marketplace plugins should switch to `make agents-install` and
  disable marketplace Superpowers copies for Sheaf work
