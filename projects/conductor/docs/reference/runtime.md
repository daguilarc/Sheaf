# Conductor Runtime Architecture

## Purpose

Conductor is the command hub service manager for this repository. It provides one
process that observes registered services, exposes service-management APIs, serves the
Conductor browser UI, and streams service log files to the browser.

Conductor-specific behavior lives in `projects/conductor`. Shared command-hub browser
presentation assets live in `projects/web`.

## Startup

The service entry point is `projects/conductor/src/main.ts`. Startup performs these
steps:

1. Discover the repository root.
2. Load `config/services.json`.
3. Find the registered `conductor` service.
4. Create the health poller for all registered services.
5. Create the HTTP and WebSocket server.
6. Bind to the host and port from the `conductor` service entry.
7. Start the health poller.

The current `conductor` registry entry binds to `0.0.0.0:9001`, uses `/` as its
`home_path`, and starts with `make conductor-run`.

## Service Registry

`config/services.json` is the source of truth for registered services. Conductor does
not maintain a separate registry or service database.

Each entry contains:

- `name`
- `host`
- `port`
- `command`
- optional `home_path`

Registry loading validates the JSON shape, rejects malformed entries, and rejects
duplicate service names.

## Health Model

`projects/conductor/src/health_poller.ts` keeps heartbeat state in memory. It creates
an initial unhealthy state for each registered service, immediately runs a poll cycle
when started, then repeats every 30 seconds.

For each service, Conductor requests:

```text
GET http://{host}:{port}/health
```

When a service is registered on `0.0.0.0`, Conductor polls `127.0.0.1` for that service
because `0.0.0.0` is a bind address rather than a client target.

Healthy responses must include `healthy: true` and numeric `uptime`. Network errors,
timeouts, invalid JSON, missing required fields, non-2xx responses, and `healthy: false`
responses update the heartbeat to unhealthy. The poller preserves the latest heartbeat
timestamp and never starts, stops, or restarts services.

## HTTP Server

`projects/conductor/src/server.ts` owns the HTTP route table. It serves:

- Conductor health at `GET /health`.
- Conductor shutdown at `POST /exit`.
- Service REST APIs under `/api/services`.
- The main browser UI at `GET /`.
- Per-service log pages at `GET /services/{service_name}/logs`.
- Shared CSS under `/assets/web/*`.
- Conductor browser JavaScript under `/assets/conductor/*`.

REST service responses are assembled by `service_presenter.ts`, which merges registry
fields with the latest heartbeat state and derives `home_url` when `home_path` is
present.

## Lifecycle Controls

Lifecycle APIs are explicit user actions. Conductor does not implement desired-state
reconciliation.

`LifecycleManager` starts services by parsing and spawning the configured command from
the repository root. Child stdout and stderr append to
`logs/<service_name>/<service_name>_stdout.log` and
`logs/<service_name>/<service_name>_stderr.log`. Stop requests prefer the target
service's `POST /exit` endpoint.
When Conductor started a process directly, it can also stop that owned process. Restart
requests stop first, then start from the same configured command.

Stopping or restarting `conductor` shuts down the backend that is serving the UI, so the
browser connection ends after the response is flushed.

## Log Access

Service logs are read from:

```text
logs/<service_name>/
```

`logs.ts` lists files recursively, ignores non-files, returns paths relative to the
service log root, and validates log paths before reads. Absolute paths, `..` traversal,
directories, non-files, and symlinks escaping the service log root are rejected.

`log_stream.ts` implements byte-range log reading for the browser:

- `open` sends a bounded tail window.
- `read_before` sends an earlier byte range using stable offsets.
- `follow` polls for appended bytes and sends append messages.
- Truncation or rotation resets the open stream and sends an error message.

Each read is capped at 65,536 bytes.

## Browser UI And Shared Assets

Conductor HTML templates are generated by `ui.ts`. Browser JavaScript lives in
`projects/conductor/src/ui/`.

The shared stylesheet is `projects/web/src/sheaf.css`, served by Conductor at:

```text
GET /assets/web/sheaf.css
```

The `web` project owns shared presentation assets only. Service logic, API calls,
lifecycle controls, and Conductor page-specific JavaScript remain in
`projects/conductor`.

## Test Coverage

The Conductor package test suite covers registry loading, repository path discovery,
health response parsing and polling, REST service responses, lifecycle behavior with
test doubles, log listing, WebSocket log streaming, static asset routing, and UI route
integration.

Run it from the repository root:

```bash
npm --prefix projects/conductor test
```
